A view names an IRI in its output and gets back rendered content. It never
learns what was behind the IRI: a note, a spreadsheet, a photo, a container
listing, a page on another origin. The rule table picks the view for the
child, and the calling view branches on nothing.

This is what a desktop does when it opens a file with the handler its MIME
type names, and what compound documents did when a spreadsheet sat inside a
presentation inside a mail. Here it runs over IRIs, so the child can live on
another machine, and none of it needs RDF, since a content type is enough to
dispatch.

## The call

```ts
type Context = {
  resolve(iri: string): Promise<Resource>
  transclude(iri: string, hint?: Hint): Promise<string>   // new
  emit(event: Event): void
  events: AsyncIterable<Event>
}
```

`resolve` hands out data, `transclude` hands out an instance. Two calls, so
a resource never has to know which of the two it currently is.

What comes back is HTML the calling view puts into its own output verbatim.
A view must not inspect it, rewrite it, or assume whether it is the finished
child or a placeholder the host fills in later. That is what lets a
server-side host answer the same call by rendering the child inline.

## A view that only composes

```ts
export const dashboardView: View = {
  id: 'https://example.org/views#Dashboard',
  when: [{ type: 'https://example.org/ns#Dashboard' }],

  async render (resource, ctx) {
    const panels = objects(resource.graph ?? [], resource.iri, PANEL)
    const html = await Promise.all(panels.map((panel) => ctx.transclude(panel.value)))
    return { html: `<div class="dashboard">${html.join('')}</div>` }
  }
}
```

Each panel is rendered by whatever view the rule table picks for it: a note
by the Markdown view, a container by the listing view, a CSV by a table
view. The dashboard knows none of them and holds no branch on content type.

## A view that does its own work

The more common case has real work of its own and still no business
rendering what it points at. A result view owns the query, the ranking, the
order, the score column, the paging and the empty state:

```ts
async render (resource, ctx) {
  const hits = rank(JSON.parse(resource.body as string))    // its own work
  const rows = await Promise.all(hits.map(async (hit) => `
    <li class="hit">
      <span class="score">${hit.score.toFixed(2)}</span>
      ${await ctx.transclude(hit.iri)}
    </li>`))
  return { html: `<ol class="results">${rows.join('')}</ol>` }
}
```

A note among the hits renders as a note, a photo as an image, and a resource
whose type this view has never heard of renders as whatever the rule table
has for it. The alternative is a branch per content type inside the view,
which is the rule table written a second time in a worse place.

## Bringing in a part

```ts
await ctx.transclude(note, { fragment: 'Setup', clip: true })
```

`clip` is what separates an embed of `note.md#Setup` from navigating to it:
the embed shows that section alone, the navigation shows the note scrolled
to it. A view that does not understand `clip` ignores it and renders the
whole resource.

Fragments are what make composition reach inside a document. A resource
like a life event carries `#ts` for its time span and `#claim-1` for a dated
claim, so a view can hand each part to the view that fits it without any of
those parts being a separate file.

## What the host does with it

A browser runtime answers `transclude` with a placeholder:

```html
<div data-aleph-transclude="https://pod.toph.so/notes/Setup.md"></div>
```

After the parent's HTML is in the document and before the parent's
`hydrate` runs, the runtime walks the region and mounts a child instance
into every placeholder. A child is an instance like any other: own region,
own handle, own dependencies, own events. An `as:Update` on the child's IRI
re-renders the child alone, and the parent does not move.

**Keyed by `(iri, hint)`.** When a parent re-renders, its placeholders are
matched against its existing children. A key that is still there keeps its
instance, and the runtime moves that child's region into the new
placeholder without calling anything on the child. A key that vanished is
disposed, and a new key is mounted. Without this, a parent that repaints
would throw away everything below it.

**Cycle and depth belong to the runtime.** Each instance carries the chain
of its ancestor IRIs. A transclusion of an IRI already in the chain, or one
past the depth limit, is answered with a marker element and no mount. Views
carry no guard of their own, because a guard per view is a bug per view.

**One cache in front of `resolve`**, keyed by the IRI without its fragment,
makes ten block transclusions of one note a single fetch. It belongs to the
host, so a server-side host that already holds a store needs none.

## What changes for the Markdown view

`![[Note]]` becomes `ctx.transclude(target)`, and `![[Note#Setup]]` becomes
one with `fragment` and `clip`. Its private embed recursion, its depth limit
and its cycle guard are deleted, since the runtime has them. An embedded
note becomes a child instance, so a wikilink click inside it is an `as:View`
from that child, and editing it re-renders it alone.

## What this opens

A layout becomes a resource that names other resources, so a home screen is
a document rather than code. A tab strip or a split pane becomes a container
of IRIs with no layout code that knows what is inside a pane. And a
compound document, a table region inside a note inside a mail, is rendered
by the view each content type selects, with every level addressable and
updatable on its own.
