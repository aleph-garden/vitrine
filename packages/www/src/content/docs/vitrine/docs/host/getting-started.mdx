A host answers `resolve`, gives the runtime a region, and delivers events.
Here is one, whole:

```ts
import { createRenderer } from '@aleph-garden/vitrine'
import { createRuntime } from '@aleph-garden/vitrine/dom'

const renderer = createRenderer({ parsers: [], views: [personCardView, checklistView] })
const runtime = createRuntime(renderer, resolve)

await runtime.mount(document.querySelector('#region'), iri)
```

That is these documentation pages. `resolve` answers from a record of
fixture resources instead of the network, which is a difference no view can
observe.

## What `resolve` is

```ts
type Resolve = (iri: string) => Promise<Resource>
```

The simplest one that works:

```ts
const resources: Record<string, Resource> = { /* … */ }

async function resolve (iri: string): Promise<Resource> {
  const resource = resources[iri]
  if (!resource) throw Object.assign(new Error(`404 ${iri}`), { status: 404 })
  return resource
}
```

Rejecting matters as much as answering. `mount` rejects when `resolve`
does, which is how a host learns that it should show a login or an error
instead of a region:

```ts
try {
  await runtime.mount(region, iri)
} catch (error) {
  if ((error as { status?: number }).status === 401) showLogin(region)
  else showError(region, error)
}
```

Building a `Resource` out of a real HTTP response is its own page:
[Resolving](/vitrine/docs/host/resolving/).

## What a host owns

Fetching, session, navigation, the address, layout, chrome. The library
decides none of it, and a view can reach none of it.

Concretely, the decisions are yours:

- **Which views exist**, and in which order. See
  [Registry](/vitrine/docs/host/registry/).
- **What an IRI means.** The browser shell reads it from `location`, these
  pages read it from an attribute, a desktop host might read it from a
  window.
- **Whether there is a session at all.** No session is a valid answer:
  these pages have none.
- **What a click on a link does.** See
  [Navigation](/vitrine/docs/host/navigation/).

## Many regions

`mount` takes an element, so a host with several regions calls it several
times and keeps whatever layout it likes around them. Each region gets its
own instance with its own dependencies and its own handle. Mounting into a
region that already holds an instance disposes the old one first.

```ts
await runtime.mount(document.querySelector('#main'), noteIri)
await runtime.mount(document.querySelector('#sidebar'), containerIri)
runtime.instances()   // both, with their regions and dependencies
```
